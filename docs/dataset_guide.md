# Dataset Guide

This document explains where the data comes from, how labels are interpreted,
where files must be placed and how to use a different dataset.

---

## 1. Why this dataset

The project needs **real URL strings** because every feature is computed by
`src/feature_extraction.py`.

The commonly used **UCI Phishing Websites** dataset (dataset ID 327) was
rejected: it contains only precomputed integer features (`having_IP_Address`,
`URL_Length`, ...) and no URL column. Training on it would not demonstrate
feature engineering from URLs and the web app could not score a pasted URL.

Instead, the project uses the **PhiUSIIL Phishing URL Dataset** (UCI dataset ID
967), which contains 235,795 labelled URLs collected from real phishing and
legitimate sources.

## 3. Label convention

The original PhiUSIIL CSV uses:

| Original value | Meaning |
|---:|---|
| `1` | Legitimate |
| `0` | Phishing |

This project normalises labels to the opposite, security-oriented convention:

| Project value | Meaning |
|---:|---|
| `1` | **Phishing / malicious** (positive class) |
| `0` | **Legitimate / benign** |

`src/data_loader.py` detects the original PhiUSIIL columns and performs the
inversion automatically. A regression test
(`test_phiusiil_label_convention_is_inverted`) protects this behaviour.

For **custom datasets**, the default assumption is the standard
`1 = positive/phishing`, `0 = negative/legitimate`. Text labels are also
accepted (case-insensitive):

| Phishing (`1`) | Legitimate (`0`) |
|---|---|
| `phishing`, `phish`, `malicious`, `malware`, `bad`, `unsafe`, `fraud`, `defacement`, `true`, `yes` | `legitimate`, `legit`, `benign`, `good`, `safe`, `ham`, `clean`, `false`, `no` |

Rows with labels that cannot be interpreted are removed and counted in
`results/dataset_summary.json`.

## 4. Where files go

```
data/
├── raw/
│   ├── urls.csv                         <- standardised dataset (url,label)
│   ├── dataset_load_report.json         <- load summary
│   ├── phiusiil.zip                     <- downloaded archive (optional)
│   └── phiusiil/
│       └── PhiUSIIL_Phishing_URL_Dataset.csv   <- extracted original
└── processed/
    └── url_features.csv                 <- generated by src.preprocessing
```

The loader searches in this order:

1. `PHISHING_DATASET_PATH` from `.env` / environment
2. `data/raw/urls.csv`
3. `data/raw/phiusiil/PhiUSIIL_Phishing_URL_Dataset.csv`
4. any other `*.csv` directly inside `data/raw/`

## 5. Setup

### 5.1 Automatic (recommended)

From the project root, with the virtual environment activated:

```powershell
python -m src.data_loader --download-phiusiil
```

Expected output:

```
INFO  PhiUSIIL dataset already present (or: Downloading ...)
INFO  Wrote standardised dataset (235,795 rows) to data\raw\urls.csv
```

Then build the feature matrix:

```powershell
python -m src.preprocessing
```

### 5.2 Manual download

1. Open <https://archive.ics.uci.edu/dataset/967/phiusiil+phishing+url+dataset>.
2. Click **Download** and save the ZIP file.
3. Extract it.
4. Either:
   - place `PhiUSIIL_Phishing_URL_Dataset.csv` at
     `data/raw/phiusiil/PhiUSIIL_Phishing_URL_Dataset.csv`, then run
     `python -m src.data_loader --download-phiusiil` (it reuses the file), **or**
   - create `data/raw/urls.csv` yourself with two columns, `url` and `label`.

### 5.3 Verify the data

```powershell
python -c "import pandas as pd; df=pd.read_csv('data/raw/urls.csv'); print(df.shape); print(df['label'].value_counts())"
```

Expected:

```
(235795, 2)
label
0    134850
1     100945
```

## 6. Using a different dataset

Any labelled URL dataset can be used if it has a URL column and a label column.

Accepted URL column names (case-insensitive):
`url`, `urls`, `link`, `uri`, `address`.

Accepted label column names (case-insensitive):
`label`, `labels`, `class`, `target`, `status`, `type`, `is_phishing`.

Example: a CSV with columns `URL` and `status` containing
`phishing` / `legitimate` works without renaming.

Then run:

```powershell
python -m src.preprocessing --dataset "C:\path\to\my_dataset.csv" --force
python -m src.model_training
python -m src.model_evaluation
```

Or point the project at it permanently:

```powershell
Copy-Item .env.example .env
notepad .env
```

```dotenv
PHISHING_DATASET_PATH=C:\path\to\my_dataset.csv
```

### Requirements checklist

- [x] Actual URL strings, not precomputed feature columns.
- [x] Both classes present (at least a few hundred rows each is advisable).
- [x] A documented label mapping.
- [x] URLs use `http://` or `https://` (scheme may be missing; it is added).
- [x] You have the right to use the data and cite its source.

### Public alternatives worth considering

| Dataset | Notes |
|---|---|
| PhiUSIIL (this project) | 235k URLs, CC BY 4.0, ready to use |
| PhishTank / OpenPhish feeds | Phishing URLs only; you must pair them with legitimate URLs (e.g. a Tranco top-sites list) |
| Kaggle "Phishing Site URLs" and similar | Check the license and URL/label columns before use |
| Mendeley / Zenodo phishing URL datasets | Varies; check version and license |

Do not mix datasets with incompatible label conventions without checking the
class balance afterwards. `results/dataset_summary.json` reports the counts and
imbalance ratio for every build.

## 7. Known characteristics and biases

- **HTTPS bias:** all 134,850 legitimate URLs use HTTPS; only about 48.6% of
  phishing URLs do. A model can learn "HTTP = phishing".
- **Homepage bias:** legitimate examples are mostly root domains, while phishing
  examples frequently include paths and query strings.
- **Feature collisions:** 202,324 rows share an identical 38-value feature
  vector with another row. Random row-level splits can therefore produce
  optimistic metrics.
- **Snapshot in time:** URL patterns drift; retrain periodically.

These points are discussed in the README's limitations section and in the EDA
notebook.
